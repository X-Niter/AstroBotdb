    Custom Commands System

    Create powerful, customized commands for your Discord server with AstroBot's intuitive custom commands system. From simple text responses to complex, dynamic interactions with external APIs and conditional logic.

    Overview

    The custom commands system lets you create unique commands specifically tailored to your community's needs. These commands can:

    Rich Responses

    Respond with text, images, embeds, and more

    Dynamic Logic

    Use variables, conditional statements, and store data

    API Integration

    Connect to external APIs and services

    Administrator Permissions Required

    Creating and managing custom commands requires Administrator or Manage Server permissions, but anyone can use the commands once they're created (unless permissions are restricted).

    Basic Custom Commands

    Let's start with the basics of creating a simple custom command: 

    !astro cc create welcome "Welcome to our server, {user.mention}! Check out {channel.mention:rules} for our server rules."

    This creates a command called "welcome" that responds with a personalized greeting, mentioning the user who triggered the command and linking to a channel called "rules".

    To use this command, members would type:

    !astro welcome

    Command Parameters

    You can create commands that accept parameters from users: 

    !astro cc create greet "Hello, {params.0}! Welcome to {server.name}."

    This command takes one parameter (a name) and incorporates it into the greeting. Users would invoke it like:

    Example Usage:

    !astro greet John

    Expected Response:

    "Hello, John! Welcome to AstroFrame Server."

    Parameter Access

    You can access parameters by index ({params.0}, {params.1}, etc.) or collect all remaining parameters with {params.all}: 

    !astro cc create echo "You said: {params.all}"

    Creating Rich Embeds

    Custom commands can create rich embeds with multiple fields, colors, images, and more. These visually appealing messages help organize information and make your commands stand out.

    Embed Features
    • Customizable colors and titles
    • Images, thumbnails, and author icons
    • Multiple fields with inline formatting
    • Dynamic content with variables
    • Footers with timestamps
    • Hyperlinks and mentions

      "icon_url": "{user.avatar_url}"
    }
  }
}}{% endraw %}
    JSON Syntax

    Note the use of double curly braces {% raw %}{{ }}{% endraw %} to define a JSON object for the embed. Within this JSON, you can use AstroBot's variables in single curly braces {% raw %}{ }{% endraw %}.

    Available Variables

    AstroBot provides many variables you can use in your custom commands. These dynamic placeholders are replaced with actual values when the command is executed.

    Variable Description Examples
    {user} The user who triggered the command
    {user.name} {user.id} {user.mention}
    {server} The Discord server (guild)
    {server.name} {server.member_count} {server.icon_url}
    {channel} The channel where the command was used
    {channel.name} {channel.mention} {channel.id}
    {params} Command parameters
    {params.0} {params.1} {params.all}
    {target} Mentioned user (if any)
    {target.name} {target.mention} {target.avatar_url}
    {time} Current time information
    {time.now} {time.utc} {time.unix}
    {random} Random value generators
    {random.number:1,100} {random.choice:A,B,C}
    Variable Formatting

    Format variables with additional options using the colon syntax:

    {time.now:date} → May 10, 2025
    {time.now:time} → 14:22:30
    {user.joined_at:relative} → 3 days ago
    {number:comma} → 1,234,567
    Advanced Usage

    Variables can be nested and used with modifiers for more complex outputs: 

    // Combine variables with text
"{user.name}'s rank is #{user.rank}"

// Access nested properties
"{server.roles.0.name}"

// Use conditionals with variables
"{if:{user.has_role:Moderator},Yes,No}"

// Transform content
"{uppercase:{server.name}}"

    Conditional Logic

    Custom commands can include conditional logic to create different responses based on various factors. This turns your commands from simple text responses into dynamic, context-aware tools.

    Condition Types
    • User role checks
    • Permission verifications
    • Time-based conditions
    • Numerical comparisons
    • Text matching
    • Server status checks
    Conditional Flow
    Command Triggered
    Check Condition
    True
    "Then" Response
    False
    "Else" Response

    Basic Conditional Example

    !astro cc create role-check {% raw %}{{
  "if": "{user.has_role:Moderator}",
  "then": "You are a moderator. You can access the staff commands.",
  "else": "You are not a moderator. You don't have access to staff commands."
}}{% endraw %}
    User with Moderator Role
    ModUser
    !astro role-check
    You are a moderator. You can access the staff commands.
    Regular User
    RegularUser
    !astro role-check
    You are not a moderator. You don't have access to staff commands.

    Nested Conditions Example

    You can also use nested conditions for more complex decision trees: 

    !astro cc create member-status {% raw %}{{
  "if": "{user.join_date:days} < 7",
  "then": "Welcome, new member! You joined {user.join_date:relative}.",
  "else": {
    "if": "{user.has_role:Regular}",
    "then": "Thanks for being a regular member!",
    "else": "You've been around for a while, consider getting more involved!"
  }
}}{% endraw %}
    Pro Tip: Comparison Operators

    Use standard comparison operators in your conditions: == (equals), != (not equals), < (less than), > (greater than), <= (less than or equal), >= (greater than or equal).

    Data Storage and Retrieval

    AstroBot's custom commands can store and retrieve data, allowing you to create commands with persistent state and memory. This powerful feature enables things like counters, user inventories, economy systems, and more.

    Data Operations
    set Store a value
    get Retrieve a stored value
    increment Increase a numeric value
    decrement Decrease a numeric value
    delete Remove stored data

    Data is stored per server. Each Discord server has its own isolated data storage.

    Command Usage Counter Example

    // Create a counter command
!astro cc create count {% raw %}{{
  "data": {
    "op": "increment",
    "key": "counter",
    "default": 0
  },
  "response": "This command has been used {data:counter} times."
}}{% endraw %}

    Execution Flow:

    1. Command retrieves the current "counter" value (defaulting to 0 if it doesn't exist)
    2. The value is incremented by 1
    3. The updated value is stored back in the database
    4. The response message includes the current counter value

    User-Specific Data Example

    You can also store data per user, which is perfect for creating user-based economies, reputation systems, or inventories: 

    // Create a cookie command that gives cookies to users
!astro cc create cookie {% raw %}{{
  "if": "{params.0}",
  "then": {
    "data": {
      "op": "increment",
      "key": "cookies:{target.id}",
      "default": 0,
      "amount": 1
    },
    "response": "{user.name} gave a cookie to {target.name}! They now have {data:cookies:{target.id}} cookies."
  },
  "else": {
    "data": {
      "op": "get",
      "key": "cookies:{user.id}",
      "default": 0
    },
    "response": "{user.name}, you have {data:cookies:{user.id}} cookies."
  }
}}{% endraw %}
    Giving a Cookie
    !astro cookie @SpaceFriend
    SpaceExplorer gave a cookie to SpaceFriend! They now have 7 cookies.
    Checking Your Cookies
    !astro cookie
    SpaceExplorer, you have 12 cookies.

    API Integration

    One of the most powerful features of AstroBot's custom commands is the ability to integrate with external APIs. This lets your commands access real-time data from countless services across the web.

    API Integration Use Cases
    • Weather forecasts and conditions
    • Game statistics and server status
    • Cryptocurrency and stock prices
    • Translation services
    • Urban Dictionary lookups
    • Movie and TV show information
    • News headlines and summaries
    • Sports scores and schedules
    API Request Flow
    User triggers command
    AstroBot makes API request
    API returns data
    Bot displays formatted response

    Weather API Example

    !astro cc create weather {% raw %}{{
  "api": {
    "url": "https://api.weatherapi.com/v1/current.json?key=YOUR_API_KEY&q={urlencode:{params.all}}&aqi=no",
    "method": "GET"
  },
  "response": {
    "embed": {
      "title": "Weather for {api.location.name}, {api.location.country}",
      "description": "Current conditions: {api.current.condition.text}",
      "thumbnail": "https:{api.current.condition.icon}",
      "fields": [
        {
          "name": "Temperature",
          "value": "{api.current.temp_c}°C / {api.current.temp_f}°F",
          "inline": true
        },
        {
          "name": "Feels Like",
          "value": "{api.current.feelslike_c}°C / {api.current.feelslike_f}°F",
          "inline": true
        },
        {
          "name": "Humidity",
          "value": "{api.current.humidity}%",
          "inline": true
        },
        {
          "name": "Wind",
          "value": "{api.current.wind_kph} km/h {api.current.wind_dir}",
          "inline": true
        }
      ],
      "footer": {
        "text": "Last updated: {api.current.last_updated}"
      }
    }
  }
}}{% endraw %}
    How The API Integration Works
    1. The api object defines the external API endpoint to call
    2. Parameters from the command are inserted into the URL with {urlencode:{params.all}}
    3. AstroBot makes the HTTP request to the API and receives JSON data
    4. The response is accessed with the {api.path.to.value} syntax
    5. All response fields are automatically available through the {api} variable
    Example Usage
    !astro weather New York
    Weather for New York, United States
    Current conditions: Partly cloudy
    Temperature
    18.3°C / 65.0°F
    Feels Like
    17.8°C / 64.1°F
    Humidity
    62%
    Wind
    8.6 km/h SW
    API Keys Security

    For API integrations that require authentication, you'll need to add the API key to your bot settings or include it in the URL (as shown in the example). Never share commands with your API keys publicly. You can use the AstroBot dashboard to securely manage API keys.

    Additional API Options

    Request Options
    method

    HTTP method (GET, POST, PUT, etc.)

    headers

    Custom HTTP headers for the request

    body

    Request body for POST/PUT requests

    timeout

    Request timeout in seconds

    Response Handling
    // Error handling
"fallback": "Weather service unavailable",

// Transform JSON
"transform": "api.current.temp_c * 9/5 + 32",

// Filter results
"filter": "api.items[?(@.type == 'movie')]",

// Cache responses
"cache": "1800" // seconds

    Command Permissions

    You can restrict who can use your custom commands and in which channels they can be used. This gives you fine-grained control over your server's functionality. 

    // Require a specific role to use a command
!astro cc permission add admin-info require-role Administrator

// Restrict a command from being used in certain channels
!astro cc permission add fun-command deny-channel #serious-discussion
    Permission Types
    require-role
    Restricts command usage to members with specific roles
    deny-role
    Prevents members with specific roles from using the command
    allow-channel
    Command can only be used in specified channels
    deny-channel
    Command cannot be used in specified channels
    cooldown
    Sets a time limit between command uses

    Poll System

    !astro cc create poll {% raw %}{{
  "if": "{params.all}",
  "then": {
    "embed": {
      "title": "📊 Poll: {params.all}",
      "description": "React with 👍 for Yes or 👎 for No",
      "footer": {
        "text": "Poll created by {user.name}"
      }
    },
    "reactions": ["👍", "👎"]
  },
  "else": "Please provide a poll question. Example: !astro poll Should we add a new channel?"
}}{% endraw %}

    This command creates a simple yes/no poll. Users can vote by adding reactions to the message. The poll is presented as an embed with the question as the title.

    Reminder System

    !astro cc create remind {% raw %}{{
  "if": "{params.0} && {params.1}",
  "then": {
    "schedule": {
      "delay": "{params.0}",
      "message": "{user.mention}, reminder: {params.1:rest}"
    },
    "response": "I'll remind you about '{params.1:rest}' in {params.0}."
  },
  "else": "Please specify a time and message. Example: !astro remind 1h Check on the event"
}}{% endraw %}
    How It Works
    1. User specifies a time duration and a message
    2. Command schedules a delayed message using the schedule feature
    3. After the specified time elapses, the bot sends a reminder message
    4. Supports time formats like 5m (5 minutes), 2h (2 hours), 1d (1 day)
    Reminder Timeline
    Now (3:00 PM)
    SpaceExplorer
    !astro remind 1h Check on the server update
    AstroBot
    I'll remind you about 'Check on the server update' in 1h.
    1 hour later
    Later (4:00 PM)
    AstroBot
    @SpaceExplorer, reminder: Check on the server update
